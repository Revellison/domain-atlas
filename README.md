# Домены → IP → диапазон → ASN → сайт оператора

[Открыть таблицу](https://revellison.github.io/domain-atlas/) · [GitHub Releases](https://github.com/Revellison/domain-atlas/releases/latest)

**Новое: еженедельный GitHub Actions, JSON в Releases и веб-таблица — см. [DASHBOARD.md](DASHBOARD.md).**
Готовая страница находится в `site/`, текущий JSON — `site/data/domains.json`, workflow — `.github/workflows/weekly-domains.yml`.
GitHub Pages публикуется через `.github/workflows/deploy-pages.yml`: данные берутся из последнего релиза и отдаются со страницей с одного домена.
Перед каждым еженедельным сканированием свежий список скачивается с https://cheburcheck.ru/whitelist/domains.csv; ошибки скачивания останавливают публикацию.

В `domains_report.csv` пять запрошенных столбцов и «Резолв через» — фактический хост, для которого получен IP.
Открывается в Excel: UTF-8 с BOM, разделитель `;`.
`run_report.ps1` дополнительно создаёт `domains_report.xlsx`, если на компьютере есть runtime Codex.

## Запуск

Требуется Python 3.10 или новее. В PowerShell, в этой папке:
`domain_report.py` и модуль `subdomain_providers.py` должны лежать рядом.

```powershell
python -m pip install -r requirements.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_report.ps1
```

Другой входной файл:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_report.ps1 -InputFile "domains.xlsx" -OutputFile "result.csv"
```

Самостоятельный Python-скрипт, без зависимости от Codex:

```powershell
python -X utf8 .\domain_report.py "domains(3).csv" -o domains_report.csv
```

CSV/TXT/XLS/XLSX, домены в первом столбце. Другой столбец: `--column 2`, другой лист Excel: `--sheet 2`.
Заголовки `domain`, `Домен`, `URL` распознаются автоматически. Повторы удаляются после нормализации.
Обрабатываются URL, IDN и домены вида `*.example.com`. Обрабатывается только IPv4, IPv6 отключён.
Один домен с несколькими IPv4-адресами занимает несколько строк.
При нескольких анонсирующих ASN один IP может также занимать несколько строк.

## Резервный поиск поддоменов

В резервные API попадают **только домены без IPv4 после обычного резолва**.
Проверяется до 20 конкретных поддоменов из API; поиск останавливается после 2 поддоменов с IPv4.
Имена за пределами исходного домена и wildcard-записи отбрасываются.
В таблице сохраняется исходный домен, а «Резолв через» показывает найденные поддомены.
IP и ASN относятся к этим поддоменам. Их размещение может отличаться от размещения других сервисов того же домена.

Подключены источники:

| Источник | Доступ | Минимальная пауза |
|---|---|---|
| Chaos | `PDCP_API_KEY` или `CHAOS_API_KEY` | 2 сек |
| Cert Spotter | Без ключа с ограниченной квотой; `CERTSPOTTER_API_KEY` при наличии | 2 сек |
| Subdomain Center | Без ключа: до 500 имён; `SUBDOMAIN_CENTER_API_KEY` при наличии | 12,5 сек без ключа |
| BufferOver TLS | `BUFFEROVER_API_KEY` | 2 сек |
| Netlas Certificates | `NETLAS_API_KEY`, доступ к коллекции сертификатов | 20,5 сек |
| Censys Platform | `CENSYS_PAT`, запросы расходуют кредиты аккаунта | 2 сек |
| crt.sh | Без ключа | 2 сек |

Ключи задаются переменными окружения. Источники с обязательным ключом пропускаются без сетевого обращения, если ключ не задан.
Ключи отправляются только в заголовках и не записываются в результат.
Chaos и Subdomain Center объединяют CT с другими источниками имён; BufferOver использует TLS-сканирование.
DNS-резолв всех выбранных имён выполняется заново независимо от IP, указанных поставщиком.

Скрипт учитывает `Retry-After`, ограничивает ответ 4 МБ и кеширует найденные имена на сутки.
Пустой успешный ответ хранится час; временная ошибка не превращается в подтверждённое отсутствие поддоменов.
HTTP-запрос ограничен 12 секундами, соединение — 5, чтение — 10. Для DNS поддомена — 4 секунды и максимум 2 попытки.
На домен отведено до 120 секунд, включая ожидание очереди API. Общий предел резервного этапа — час.
Это позволяет пройти весь список с бесплатным лимитом Subdomain Center 5 запросов/мин.
После трёх последовательных сетевых ошибок источник отключается до следующего запуска с сохранением паузы.
Отказ Cert Spotter по конкретному домену не отключает обработку остальных доменов.

Доработать только записи без IPv4 из текущего отчёта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_report.ps1 -RetryUnresolved
```

Либо Python без экспорта Excel:

```powershell
python -X utf8 .\domain_report.py "domains(3).csv" --retry-unresolved
```

Настройки: `--ct-providers subdomaincenter,certspotter,crtsh`, `--ct-candidates 20`, `--ct-sample 2`,
`--ct-timeout 12`, `--ct-dns-timeout 4`, `--ct-budget 3600`. `--no-ct` отключает резервный этап.
Если API недоступен или исчерпана квота, запись отмечается как неполная; подробная причина есть в `details.json`.

## Группировка

Порядок строк: **организация оператора → ASN → домен → IP → префикс**.
Если PeeringDB сообщает, что несколько ASN принадлежат одной организации, они идут рядом.
При отсутствии такой записи группировка идёт по названию оператора и ASN.
Неизвестные ASN и ошибки DNS находятся в конце. Сортировка входит в Python-скрипт и действует также для CSV.

## Скорость и ограничения

- DNS: Google DNS-over-HTTPS, до 32 одновременно выполняемых запросов, до 40 запросов/сек, включая повторы.
  Используются только записи A (IPv4).
- Team Cymru: до 1000 уникальных IP в одном bulk WHOIS запросе, минимум 2 секунды между пакетами.
- При недоступности TCP/43 — резервный DNS TXT, до 10 запросов/сек к Team Cymru, включая повторы.
- PeeringDB: до 150 ASN за запрос, минимум 4 секунды между обращениями, включая повторы.
- Для HTTP 429/5xx учитывается `Retry-After`, повторные попытки используют увеличивающиеся паузы.
  Если сервер просит ждать более 180 секунд, обращения прекращаются, а результат сохраняется без недоступных сайтов.
  Пауза сохраняется в SQLite и учитывается следующим запуском. Это действует и для DNS-over-HTTPS.
- SQLite-кеш `.domain_cache.sqlite3`: DNS — до TTL записи, не более часа. Отрицательные ответы DNS — 5 минут.
  BGP — 4 часа. Сайты — 7 дней, отсутствие записи в PeeringDB — сутки.
  Временные ошибки сети не кешируются как отсутствие данных.
- После Ctrl+C повторите ту же команду: готовые DNS-ответы и пакеты берутся из кеша.
  При истечении TTL соответствующие данные будут запрошены снова.

Лимиты внешних сервисов зависят и от других пользователей того же внешнего IP.
Скрипт сокращает число обращений и корректно обрабатывает ограничения, но гарантировать отсутствие 429 нельзя.

Для медленного соединения: `--workers 12 --dns-qps 15`. Для теста: `--limit 20`.
Системный DNS вместо HTTPS: `--dns-transport system`.
Явный обычный DNS: `--nameserver 1.1.1.1 --nameserver 8.8.8.8` (автоматически выбирает транспорт `system`).
API-ключ не обязателен. Если есть ключ PeeringDB, задайте переменную `PEERINGDB_API_KEY`.

## Что означают данные

Диапазон — **BGP-префикс**, ASN — сеть, анонсирующая этот диапазон. Это не утверждение о юридическом владельце IP-блока.
Cloudflare, Akamai и Fastly обозначены как CDN по соответствующим ASN. В других случаях выводится название сети из источника.
Показывается оператор публичного IP домена, включая CDN. Общие сети Amazon и Google не объявляются CDN без дополнительных данных.

Сайт берётся из записи оператора в PeeringDB. Если записи или сайта нет, выводится **«Не найден»**.
Адреса сайтов не составляются из названий компаний и не подменяются поисковыми ссылками.
PeeringDB не охватывает всех операторов; поэтому отсутствие сайта не означает отсутствие оператора.
DNS зависит от места и времени запроса, географической балансировки и используемого резолвера.

`domains_report.details.json` содержит исходные статусы DNS, ошибки сервисов, номер организации PeeringDB,
ссылку на запись каждого оператора, источник BGP и время проверки. Этот файл использует и экспорт XLSX.
